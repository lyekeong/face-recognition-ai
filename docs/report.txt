1. Introduction
================================================================================

1.1 Background

Face recognition is one of the most widely studied problems in computer vision
and artificial intelligence. It refers to the ability of a computer system to
detect a human face in an image or video frame, and then identify the identity
of the person by matching the detected face against a set of known identities.
The technology is used in many real-world applications, including smartphone
unlock, automated attendance systems, access control and security
surveillance, border control, e-banking verification, and social-media photo
tagging. Because a face is a natural, non-intrusive and contactless biometric
signal, face recognition is usually more convenient and faster than
fingerprint or iris based approaches.

The problem is not trivial. A human face changes appearance with pose, facial
expression, illumination, age, accessories such as glasses, and image quality.
A robust face recognition system must therefore combine two main stages: (1)
face detection, i.e. locating where the face is in the image, and (2) face
identification, i.e. extracting a discriminating representation of the face
and classifying it into one of the known persons. These two stages can be
implemented with very different technologies, ranging from classical
hand-crafted features with traditional machine-learning classifiers to modern
deep-learning networks that learn the features automatically from a large
dataset.

This assignment is a group project for the BMCS2203 Artificial Intelligence
course. The group selected Title 6, "Image Processing and Computer Vision",
with the specific research area of Face Recognition. In line with the
assignment requirement that each group member contributes a solution using a
different algorithm, the project implements and compares three different
approaches built by the three team members:

  * A custom Convolutional Neural Network (CNN) - Lye Wei Keong
  * A YOLO (You Only Look Once) face detector combined with a transfer-learned
    ResNet18 classifier - Louis Lim Yi Jie
  * A classical machine-learning pipeline using Histogram of Oriented
    Gradients (HOG) features with a Support Vector Machine (SVM) classifier -
    Tan Kah Chao

All three solutions are developed with the Python programming language and are
combined with face-detection and image-processing tools (OpenCV and the YuNet
face detector) so that they can be compared fairly on the same dataset and the
same evaluation process. A graphical user interface (GUI) with image upload and
live webcam recognition was also built so that the system can be demonstrated
in a real-life scenario.

1.2 Problem Statement

Although face recognition has advanced rapidly, there is still a practical
problem: different algorithmic families have very different behaviour, and it
is difficult to know which approach to choose without a fair, systematic
comparison. Classical machine-learning methods such as HOG + SVM are light and
fast and can run on an ordinary CPU, but their accuracy is often lower and
they tend to produce over-confident or uncertain predictions when the face is
not in their training list. Deep-learning methods such as modern CNNs and
transfer-learned networks achieve much higher accuracy, but they require more
compute power and larger amounts of training data.

A second issue is the "unknown face" problem. Most classifiers are open-set by
design only in theory: they always output one of the trained classes, so a face
that does not belong to any trained person will still be assigned to someone.
In a real deployment, the system should reject such faces as "Unknown" instead
of making a wrong identification. Designers therefore need to add a confidence
threshold (gate) and must understand the trade-off between precision (the
proportion of accepted labels that are correct) and recall (the proportion of
true faces that are actually recognized).

Within this student group, there was also a practical gap: the three members
proposed three different algorithms, but it was not yet clear how the results
of these algorithms compare on the same task, dataset, preprocessing pipeline
and evaluation metric. This suggests the following research questions:
  * How accurately can each of the three approaches (CNN, YOLO + ResNet18,
    HOG + SVM) identify faces on the same evaluation dataset?
  * How well does each approach behave when it is allowed to reject unknown or
    uncertain faces using a confidence gate?
  * Which approach offers the best overall performance, and what are the
    respective advantages and disadvantages of each method?

1.3 Objectives/Aims

The objectives of this project are:

 1. To build a complete face recognition system in Python that can detect a
    face in an image or a live webcam frame, crop and pre-process the face,
    and identify the person from a predefined set of 17 celebrities.
 2. To implement three different face recognition solutions using three
    distinct algorithms, one per group member:
       (a) a custom Convolutional Neural Network (CNN);
       (b) a YOLO face detector with a transfer-learned ResNet18 classifier;
       (c) a HOG feature based Support Vector Machine (SVM) classifier.
 3. To pre-process and augment the selected dataset (face detection, face
    alignment, contrast enhancement, resizing, normalization, and data
    augmentation) so that it is suitable for training the three models.
 4. To evaluate and compare the three methods using standard metrics -
    accuracy, precision, recall, and F1 score - on the same held-out test set,
    and to analyse the unknown-face rejection behaviour of each method.
 5. To provide a graphical user interface that allows users to recognize faces
    from an uploaded image or from a live webcam using any of the three
    models, so that the system can be demonstrated in a real-life scenario.

1.4 Significance / Contribution of the Study

The study contributes to the learning outcomes of the course by demonstrating
a complete cycle of an intelligent-system development: problem analysis,
background study, dataset preparation, algorithm design, training, evaluation,
comparison and deployment as a working prototype.

From a practical point of view, the project provides a fair, side-by-side
comparison of three different algorithm families for face recognition on the
same dataset and evaluation procedure. Such a comparison helps practitioners
choose an approach that suits their constraints: for example, whether high
accuracy matters more than processing speed, or whether the target device is a
GPU workstation or an inexpensive CPU-only machine.

The project also addresses the unknown-face issue, which is one of the main
sources of false acceptance in face recognition systems. By measuring the
precision and recall of each model at its confidence gate, the study shows
exactly how much safety the unknown-rejection mechanism adds to each method,
and where this safety costs recall.

Finally, because the whole system is implemented with widely used,
well-documented open-source tools (Python, OpenCV, PyTorch, Torchvision,
scikit-learn and Ultralytics), the prototype is reproducible and can be reused
by other students as a learning resource and as a base for future improvement,
such as the use of face embedding methods (FaceNet or ArcFace), larger
datasets, and edge-device deployment.

2. Related Work
================================================================================

2.1 Review of previous studies

Face recognition research can be roughly divided into classical (holistic and
structural) approaches and modern deep-learning approaches.

The earliest successful methods treated a face image as a whole vector of
pixel values and used linear methods to reduce its dimensionality. Turk and
Pentland (1991) proposed the "Eigenfaces" method, which applied Principal
Component Analysis (PCA) to face images so that a face could be represented by
a small number of basis images, and recognition was performed by nearest
neighbour matching in the reduced space. This method was important historically
because it showed that face images live in a much lower-dimensional space than
the raw pixel space. Later, Belhumeur, Hespanha and Kriegman (1997) extended
this idea with Linear Discriminant Analysis (LDA) in the "Fisherfaces" method,
which maximises between-class separation and therefore usually recognized
better than Eigenfaces under varying illumination.

For the detection stage, Viola and Jones (2001) introduced a real-time
framework using Haar-like features, an integral image and a cascade of
AdaBoost classifiers, which dominated practical face detection for more than a
decade and is still available as cv2.CascadeClassifier in OpenCV.

A second line of classical work uses local structural features instead of raw
pixels. Dalal and Triggs (2005) introduced the Histogram of Oriented Gradients
(HOG) descriptor for human detection, where histograms of gradient
orientations over small cells are normalized over blocks. Ahonen, Hadid and
Pietikainen (2006) proposed Local Binary Patterns (LBP) histograms, a
texture-based face representation, and achieved very good recognition accuracy
on the FERET database. These hand-crafted feature descriptors are cheap to
compute, lighting-robust to some degree, and can be paired with classifiers
such as the Support Vector Machine (SVM) (Cortes and Vapnik, 1995) or
nearest-neighbour. The SVM, in particular, became the standard classifier for
hand-crafted features because of its good generalization on high-dimensional
descriptors.

The deep-learning era changed both feature extraction and classification
simultaneously. Krizhevsky, Sutskever and Hinton (2012) showed with AlexNet
that a deep Convolutional Neural Network (CNN) trained on millions of images
can learn discriminative features automatically and outperforms hand-crafted
methods by a large margin on ImageNet. Simonyan and Zisserman (2014) showed
that depth matters and proposed the VGG networks, while He, Zhang, Ren and Sun
(2016) introduced the Residual Network (ResNet) with skip connections,
allowing very deep networks to be trained successfully. Deep networks are
often not trained from scratch for a new task; instead, a network pre-trained
on a large dataset such as ImageNet is fine-tuned on the target data, an
approach known as transfer learning. This makes deep learning affordable even
with a relatively small training set, which is exactly what this project does
with ResNet18 on the celebrity dataset.

For face recognition specifically, deep methods were first applied to
classification. Taigman, Yang, Ranzato and Wolf (2014) built DeepFace, which
combined a deep network with a 3D face alignment step and reached near-human
accuracy on the Labeled Faces in the Wild (LFW) benchmark. Schroff, Kalenichenko
and Philbin (2015) proposed FaceNet, which learns a compact embedding vector
for each face using a triplet loss so that faces of the same person are grouped
closely together in the embedding space and different persons are pushed apart.
Later methods such as SphereFace (Liu et al., 2017) and ArcFace (Deng et al.,
2019) improved the loss function (angular margin losses) to make the learned
embeddings even more discriminating for open-set recognition.

For object detection, of which face detection is a special case, modern methods
are also deep-learning based. Redmon, Divvala, Girshick and Farhadi (2016)
proposed YOLO ("You Only Look Once"), which treats detection as a single
regression problem and predicts bounding boxes and class probabilities in one
forward pass, allowing real-time detection. Ultralytics later developed the
YOLOv5 and YOLOv8 series, which are the most widely used implementations today.
OpenCV also released the YuNet face detector in the OpenCV Zoo, a lightweight
CNN-based detector that detects faces and facial landmarks (eyes, nose and
mouth corners) very efficiently, and is used in this project for the CNN and
HOG + SVM pipelines.

2.2 Research gap and justification for the current study

The works reviewed above show that classical methods (PCA, LBP, HOG + SVM)
and deep-learning methods (CNN classification, transfer-learning, YOLO
detection, metric-learning embeddings) each solve the face recognition problem
with very different resources and behaviour. However, most published studies
focus on a single method, on large laboratory benchmarks (LFW, CelebA, etc.),
and on identification only. In a student assignment environment, there are
three gaps that remain under-explored:

 1. Missing fair, small-scale comparison. Few studies compare a classical
    pipeline, a custom CNN, and a detection + transfer-learning pipeline on
    the SAME processed dataset, detection tool and evaluation procedure.
    Because papers report on different datasets, it is difficult to conclude
    which algorithmic family is most suitable under a fixed, limited data and
    compute budget.

 2. Missing unknown-face behaviour. Recognition accuracy alone does not tell
    how a model handles faces that are not part of the trained identities.
    Classical classifiers and neural classifiers behave differently in their
    confidence values, and it is unclear which method can reject strangers
    most safely when a confidence gate is applied.

 3. Missing detection-stage effect. Studies frequently report classifier
    accuracy but ignore the face detection stage. In a real pipeline, a face
    that the detector fails to find can never be recognized, so the
    end-to-end accuracy is usually lower than the classifier accuracy. This
    project therefore measures both the pure classifier accuracy and the
    end-to-end pipeline accuracy.

This study addresses these gaps by implementing three genuinely different
solutions (custom CNN, YOLO + transfer-learned ResNet18, and HOG + SVM) that
all share the same dataset, the same held-out test set, the same metric
formula and the same confidence-gate analysis, and by reporting both classifier
and end-to-end results. The study is justified because the outcome helps a
practitioner - and the student team - to choose an appropriate face
recognition approach under realistic constraints of accuracy, speed and
hardware, which is the core learning objective of this assignment.

3.2 Description and analysis of dataset

The dataset is the "Celebrity Face Images Dataset" published by Jefril Amboy on
Kaggle. It consists of face images of celebrities collected from the Internet,
label-organized into one folder per celebrity. From the original collection,
17 celebrities were selected for this project (e.g. Angelina Jolie, Brad Pitt,
Johnny Depp, Scarlett Johansson, Tom Cruise, Will Smith, and others). Two
celebrities whose images were insufficient or very noisy were dropped so that
every class has a reasonably balanced number of samples.

Data structure. Each class folder contains original images. For this project
the images were split per class into 80% training and 20% testing (as an
example, class "Angelina Jolie": 80 training + 20 testing images). One class,
Scarlett Johansson, had more images available and therefore ended up with 160
training and 40 testing images. Overall the working dataset contains:

  * Training set: 17 classes, 4320 images after augmentation
        - original images: 1440 (80 per class, Scarlett 160)
        - augmented copies: 2880 (brightness + horizontal-flip variants)
  * Test set: 17 classes, 360 images (20 per class, Scarlett 40)

Data pre-processing and representation. All images go through a common
pre-processing pipeline before model training:

 1. Face detection. Faces are located with a face detector (YuNet). Images
    where no face is found are still used, but the whole image is taken as a
    fallback crop so that no training sample is lost.
 2. Face alignment. The detected eye positions are used to compute a rotation
    angle; the image is rotated so that the eyes are roughly horizontal, which
    removes pose-induced rotation.
 3. Cropping with margin. The face bounding box is expanded by about 20%
    around the face to keep the hairline and chin, then cropped.
 4. Contrast enhancement. Histogram equalization is applied with CLAHE
    (Contrast Limited Adaptive Histogram Equalization, clip limit 2.0,
    tile grid 8x8) to reduce the effect of uneven illumination.
5. Resizing and normalization. Cropped faces are resized to a fixed input
    size per model (96x96 for the CNN, 224x224 for ResNet18, 224x224 for the
    refined HOG pipeline) and pixel values are normalized with the ImageNet
    mean/std (0.485, 0.456, 0.406 / 0.229, 0.224, 0.225) for the deep models.
 6. Label encoding. Class names are mapped to integer indices (0 to 16) for
    the CNN and YOLO classifiers, and kept as a label map (dictionary) for
    the SVM.
 7. Data augmentation. During training the CNN applies random horizontal
    flips, rotation (+/- 8 deg), affine translation/scale and color jitter;
    ResNet18 applies random resized crops, flips, rotation, color jitter and
    random erasing. In addition, the training dataset itself was duplicated
    with brightness-adjusted and horizontally-flipped copies (the "_bright"
    and "_flip" images visible in the dataset folders), increasing the
    training set size 3x. This augmentation helps generalization with a
    relatively small dataset.

Preliminary data analysis. Each of the 17 classes is a binary (two-class)
label problem; the recognition target is the person identity. The dataset is
roughly balanced (80 images per class in training, 20 per class in testing)
except for Scarlett Johansson which has twice as many samples. This minor
imbalance is handled in evaluation by reporting macro-averaged precision,
recall and F1, which treats every class equally.

3.3 Algorithm selection & description of algorithm(s)

Three different algorithms were selected, one per group member, covering one
classical machine-learning method and two deep-learning methods.

3.3.1 Custom Convolutional Neural Network (CNN) - Lye Wei Keong

A custom CNN is trained from scratch to classify a 96x96 aligned face crop
into one of 17 persons. The network (class FaceRecognitionCNN) consists of a
"stem" of four convolutional blocks: each block applies two 3x3 convolutions
with batch normalization and ReLU activation, followed by a 2x2 max pooling
and a 25% dropout. The channel sizes grow from 32 to 64, 128 and 256. The
"head" applies global average pooling, flattens the tensor, and ends in a
256-neuron hidden layer (with ReLU and 50% dropout) followed by a 17-neuron
linear layer producing class scores.

Training details. Cross-entropy loss with label smoothing (0.1); Adam
optimizer with base learning rate 3e-4; a warm-up phase (5% of training) that
raises the learning rate from 1e-5, followed by a cosine annealing schedule
down to 2% of the base rate; 80 epochs maximum with early stopping (patience
15 epochs on validation accuracy); batch size 32; train/validation split 85/15
percent (stratified, random seed 42). The best validation checkpoint is kept.
After training the model is evaluated on the held-out test set, producing
metrics.json, a classification report, a confusion matrix and the training
history figure. At inference the CNN is fed face crops detected by the YuNet
face detector; its softmax confidence is compared against a threshold of 0.80;
faces scoring below 0.80 are labelled "Unknown".

3.3.2 YOLO detector + transfer-learned ResNet18 classifier - Louis Lim Yi Jie

The YOLO specialization combines a modern detection network with transfer
learning on a pre-trained classifier. Face detection uses the YOLOv8n-face
model (Ultralytics, a YOLOv8n variant trained on face detection). The detected
face boxes are expanded by 20% and cropped, and each crop is then classified by
a ResNet18 model.

Transfer learning. The classifier is a ResNet18 network pre-trained on
ImageNet (torchvision.models.resnet18 with default weights). The final
fully-connected layer is replaced by a dropout layer (0.3) plus a linear layer
to 17 classes, and the whole network is fine-tuned on the celebrity dataset.
This allows the network to start from general image features (edges, textures,
object parts) learned from millions of images, which is a major advantage when
the target dataset is small.

Training details. Input size 224x224; stochastic gradient descent (SGD) with
momentum 0.9, learning rate 1e-3 and weight decay 5e-4; cosine annealing
schedule; cross-entropy loss with label smoothing (0.1); 60 epochs maximum
with early stopping (patience 10); train/validation split 90/10 (stratified,
seed 42); batch size 32; random resized crop, flip, rotation, color jitter and
random erasing as augmentation. The best validation checkpoint is saved
(output/resnet18_faces.pth) together with architecture metadata
(output/arch.json: backbone, number of classes, class names, validation and
test accuracy). At inference, YOLO faces with confidence below 0.70 are
discarded and the ResNet18 softmax confidence must reach 0.80 for a known face
to be labelled, otherwise the face is marked "Unknown".

3.3.3 HOG features + SVM (classical machine learning) - Tan Kah Chao

The classical solution uses hand-crafted features with a conventional
classifier, which is the traditional machine-learning approach and requires no
GPU.

Feature extraction. Each face is aligned and cropped with a margin of 20% -
the highest-confidence detected face is used without a minimum face size,
mirroring the CNN pipeline (refined version, ml_v2.py) - then converted to
grayscale, CLAHE-enhanced and resized to 224x224. A Histogram of Oriented
Gradients (HOG) descriptor is computed with cell size 16x16 pixels, block size
2x2 cells and 12 orientation bins. Gradients are computed by central
differences and each cell accumulates a histogram of unsigned gradient
orientation (0 to pi); the cell histograms are concatenated over blocks and
L2-normalized, producing a high-dimensional descriptor vector (about 8,100
features with the 16x16-pixel cell setting used in the refined v2 pipeline).

This crop strategy deliberately differs from an earlier prototype that
required a detected face of at least 80x80 pixels and otherwise fell back to
classifying the whole image; measurements showed that over half of the test
images then produced background-dominated features, which hurt accuracy.

Dimensionality reduction. The HOG vectors are standardized (StandardScaler,
fit on the training data only) and reduced with Principal Component Analysis
(PCA) to 1200 components (retaining 93% of the variance, randomized SVD
solver, stored as float32), so that the SVM works on a compact, well-
conditioned feature space while keeping the essential gradient structure.

Classification. A Support Vector Machine with radial basis function (RBF)
kernel is used. The hyper-parameters C (1, 10, 100) and gamma ("scale",
0.001) are tuned with a full GridSearchCV (3-fold, stratified) on an 85/15
sub-split of the training data. The final model is a CalibratedClassifierCV
wrapping the SVC with isotonic calibration (5-fold), so that the raw decision
values are converted into well-calibrated class probabilities, which are
needed for the unknown-rejection gate. Training uses a dedicated
feature-preprocessing artifact (preprocess_v2_crop.pkl) storing the class
map, scaler, PCA, HOG settings and image size, and the trained model is saved
as svm_model_v2_crop.joblib. At inference the same extraction is applied to
the highest-confidence detected face. (The GUI ships the original 128x128
detector-gated model svm_model.joblib; the refined v2 model is the reference
behind the evaluation numbers reported in Section 4.)

3.4 Evaluation metrics

All three models are evaluated on the same held-out test set (360 images).
For each test image the pipeline detects, crops and classifies the face, and
the predictions are compared with the true labels. Where the detection stage
fails or the gate rejects the face, the behaviour is also recorded.

The following metrics are computed:

  * Accuracy: the fraction of correctly classified test samples
    (correct predictions / total predictions).
  * Precision (macro): per-class precision (true positive / (true positive +
    false positive)) averaged over all 17 classes, so every class contributes
    equally regardless of size.
  * Recall (macro): per-class recall (true positive / (true positive + false
    negative)) averaged over all 17 classes.
  * F1 score (macro): the harmonic mean of precision and recall for each
    class, averaged over the 17 classes.

Additional metrics for unknown-face analysis:

  * Gate precision and gate recall: after applying the confidence gate, gate
    precision is the fraction of accepted (above-threshold) predictions that
    are correct, and gate recall is the fraction of all true faces that are
    correctly accepted. A high gate precision means the system rarely labels
    a stranger with a wrong name; a low gate recall means many real faces are
    rejected as unknown.
  * Pipeline accuracy: for the YOLO pipeline (which has a real detection
    stage), accuracy is also reported (a) counting images where YOLO found no
    face as wrong, and (b) considering only the images where a face was
    detected. This shows the effect of the detection stage on the end-to-end
    system.

A single comparison table (comparison/comparison.csv) and a grouped bar chart
(comparison/comparison.png) summarize the four main metrics of the three
methods, and a confusion matrix is generated for each model
(cnn/outputs_cnn/confusion_matrix.png, yolo/output/confusion_matrix.png,
machine learning/output_v2_crop/confusion_matrix.png for the refined SVM,
with the original detector-gated variant archived under machine
learning/output/confusion_matrix.png).

    features, PCA to 1200 components restoring 93% of the variance, full grid
    search, v2 pipeline) the classical model reached 0.767 accuracy with macro
    precision 0.776, recall 0.754 and F1 0.754 (was 0.481 with the original
    128x128 detector-gated pipeline). Its calibrated confidence is still soft
    (mean 0.675, median 0.727, maximum 0.864), so the gate is kept at 0.50 and
    accepts 309 of 360 test faces with precision 0.845 and recall 0.725;
    raising the gate to 0.65 increases precision to 0.922 and at 0.70 to 0.937,
    at recall 0.619 and 0.539 respectively.

4.2 Discussion / Interpretation

The results confirm that deep learning leads on raw accuracy: the transfer-
learned YOLO + ResNet18 pipeline has the highest raw accuracy (0.883
classifier / 0.713 end-to-end detected), closely followed by the custom CNN
(0.806). After the feature/pipeline refinement, the classical HOG + SVM
follows at 0.767 - a much narrower gap than the original 0.481. On the
balanced macro metrics, the ranking is less one-sided: the CNN has the best
macro precision/recall/F1 (0.835/0.800/0.801), while the refined SVM
(0.776/0.754/0.754) edges ahead of the ResNet18 classifier metrics
(0.738/0.637/0.633), whose best asset is raw accuracy.

Accuracy of the deep models. ResNet18 starts from ImageNet features that are
already highly general, and fine-tuning only needs to adapt these features to
faces; this is why it reaches the best accuracy despite a small dataset. The
custom CNN has to learn all features from scratch from only 4320 training
images, so a slightly lower 0.806 accuracy is expected and is still very good
for a purely from-scratch model. Its macro metrics (0.835/0.800/0.801) are the
most balanced of the three, suggesting that the CNN mistakes are spread evenly
across the classes rather than concentrated in any single person. The fact
that the refined HOG + SVM now trails the CNN by only about 0.04 accuracy
shows how much of the original gap came from the pipeline's detection-gate
noise rather than from the features themselves.

The classical method's performance. After refinement the HOG + SVM pipeline
reaches 0.767 accuracy - much better than the original 0.481 (the v1 detector
gate made over half the test images fall back to whole-image features) - and
it is now close to the deep models on the macro metrics. Hand-crafted features
still miss the high-level semantic content that deep networks learn, but on
this controlled, near-frontal dataset the loss is small. Its main remaining
weakness is confidence calibration: even with more features, isotonic-
calibrated confidence rarely exceeds 0.86 (worst-case maximum on the test set
is 0.864), so a high-safety gate would reject many genuinely known faces, and
the low gate of 0.50 allows some false acceptances (gate precision 0.845). On
a CPU-only machine, however, this model has a strong advantage - it is by far
the fastest to run and requires no GPU and no deep-learning runtime, which is
exactly the trade-off classical methods offer.

Unknown-face behaviour. The gate analysis is the most important practical
result. The YOLO pipeline achieves the safest unknown rejection: at threshold
0.80, gate precision 0.971 means almost every Accepted label is correct, at
the price of recall 0.183 (most genuinely known faces are rejected as
"Unknown" to be safe). The HOG + SVM model at its gate 0.50 is more permissive
(recall 0.725, accepting 309 of 360 faces) at precision 0.845, and the CNN
gate was exercised live at 0.80. This is the classic
precision/recall trade-off of a rejection knob, and a designer must choose the
threshold according to the application: a high threshold for security, a lower
one for convenience. The practical consequence during the prototype demo was
consistent: when the CNN and YOLO confidently recognized a trained celebrity,
they almost never misnamed an untrained face, while the SVM, with its lower
gate, was the most permissive of the three.

Detection-stage effect. The difference between the ResNet18 pure classifier
accuracy (0.883) and the pipeline accuracy (0.653 all / 0.713 detected) shows
that the detection stage is a real bottleneck: under the configured size and
confidence rules, YOLOv8n-face produced an acceptable face on only 157 of the
360 test images (44%), and the remaining 203 faces were never officially
classified (the pipeline falls back to classifying the whole image). Reporting
only classifier accuracy would overstate the real system. The refined SVM and
the CNN use the same YuNet detector family with a relaxed margin crop, and
both were evaluated on every test image.

Implications. For the practical question of "which method to choose", the
results support the following recommendations: (a) when accuracy and safety
matter and a GPU is available, use the deep-learning solutions (YOLO +
ResNet18 or the CNN); (b) when a quick, CPU-only or embedded deployment is
needed and some accuracy can be sacrificed, the HOG + SVM pipeline is a
reasonable fallback; and (c) in every case the confidence gate should be
tuned for the specific precision/recall needs of the application. The minor
imbalance of the Scarlett Johansson class (two times more samples) did not
distort the macro metrics, and no single class dominated the confusion
matrices, which confirms the evaluation procedure was fair across methods.

5.1 Achievements

The project successfully fulfilled its objectives:

 1. A complete face recognition system was built in Python with face
    detection, face alignment, cropping, pre-processing, classification and
    an unknown-face gate, exposed through a graphical user interface that can
    recognize faces from an uploaded image or from a live webcam.
 2. Three different solutions were implemented, one per group member: a custom
    Convolutional Neural Network (Lye Wei Keong), a YOLO face detector with a
    transfer-learned ResNet18 classifier (Louis Lim Yi Jie), and a HOG + SVM
    classical machine-learning pipeline (Tan Kah Chao).
 3. The dataset was prepared with a full pre-processing pipeline (YuNet face
    detection, eye-based alignment, margin cropping, CLAHE enhancement, fixed
    resizing, normalization, label encoding) and enlarged 3x with brightness
    and horizontal-flip augmentation.
 4. All three methods were evaluated on the same 360-image test set with
    accuracy, macro precision, recall and F1 score, and also analysed with a
    confidence gate for unknown-face rejection, and with pipeline accuracy.
    The comparison is stored in comparison/comparison.csv and
    comparison/comparison.png.
 5. A working prototype GUI was provided and successfully demonstrated in the
    demo: e.g., a test image of Scarlett Johansson was identified by
    all three backends (CNN 90%, YOLO 91%, and the refined SVM 69%).

5.2 Limitations and Future Works

Limitations of the current system:

  * Dataset scale and scope. The system is trained on only 17 celebrities and
    4320 training images, so it only works for these people; any other face is
    rejected as unknown. A face outside this list, or a very pose/lighting
    variant of a listed person, may still be misclassified.
  * No identity embeddings. The CNN and ResNet18 use classification
    (predictions and softmax confidence) rather than metric embeddings
    (FaceNet/ArcFace style), so new users cannot be added without retraining.
* Detection bottleneck. Under the configured size and confidence rules the
    YOLO face detector accepted faces in only 157 of the 360 test images
    (44%); the faces it misses are never classified, which directly lowers
    end-to-end accuracy.
* Classical method limitation. Even after refinement the HOG + SVM model is
    substantially less accurate than the deep models, and its calibrated
    confidence rarely exceeds 0.86, so a high-safety gate would reject most
    faces.
  * Single-person design for HOG + SVM. In the current GUI the SVM backend
    processes only the largest face in a frame, whereas the deep models
    support multiple faces.
  * No liveness/anti-spoofing. The prototype does not distinguish a real
    person from a photo or video replay, which limits security usage.

Future works:

  * Switch to embedding-based recognition (FaceNet, ArcFace or a Siamese
    network) so that arbitrary new identities can be enrolled without
    retraining, and open-set recognition becomes natural.
  * Enlarge the dataset with more celebrities and more varied poses,
    expressions, illuminations and occlusions, and use larger detectors such
    as YOLOv8m/s to reduce detection failures.
  * Add the per-image gated evaluation for the CNN and SVM backends so that
    all three methods share the same gate analysis table.
  * Optimize the deep models for edge devices through quantization and ONNX
    export, and keep the classic HOG + SVM as a fast offline mode.
  * Add multi-face support to the HOG + SVM backend and integrate a simple
    anti-spoofing check (e.g. blink detection or face-depth estimation).
